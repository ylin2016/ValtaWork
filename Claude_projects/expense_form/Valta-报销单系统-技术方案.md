# Valta 报销单系统 · 技术方案

*v0.1 · 2026-08-14 · 待确认项已用 ⚠️ 标出*

---

## 0. 一句话目标

一个不需要登录的表单页面：填完信息 + 拍收据上传 → 文件按统一规范自动改名并归档到 Drive 对应文件夹 → 后台同步落一行结构化流水 → 月底一键出汇总表 + QuickBooks 导入文件。

---

## 1. 关键约束（来自你的选择）

| 约束 | 影响 |
|---|---|
| 清洁工、维修工也要填 | **不能用 Google Form**（带附件上传时强制登录 Google 账号）。必须自建表单 |
| 提交人多为手机操作 | 移动优先设计，收据要能直接调摄像头拍 |
| VA 团队在菲律宾，本地工人说英语，你说中文 | 界面**中英双语切换** |
| 数据要能进 QuickBooks | 字段必须从一开始就带上 Location / Class / 科目三个维度 |
| 要出月度汇总报表 | Sheet 结构要规范化（一行一条，不合并单元格） |
| 房源清单你提供 | 做成一张独立的 `Properties` 配置表，改房源不用改代码 |

## 2. 数据模型

### 2.1 表单字段

| # | 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| 1 | 提交人 Submitter | 下拉 + 其他 | ✅ | 从 `People` 配置表读取 |
| 2 | 消费日期 Date | 日期 | ✅ | 默认今天，不可选未来 |
| 3 | 房源 Property | 可搜索下拉 | ✅ | 从 `Properties` 配置表读取；含"非房源/公司通用"选项 |
| 4 | 实体 Entity | *自动带出* | — | Trust / Valta Realty，由房源决定 |
| 5 | 费用科目 Category | 按钮组 | ✅ | 见 2.3 科目表 |
| 6 | 商家 Vendor | 文本 + 常用建议 | ✅ | Home Depot / Costco / Amazon… |
| 7 | 金额 Amount | 数字 | ✅ | 含税总额，USD |
| 8 | 支付方式 Payment | 单选 | ✅ | 个人垫付（需报销）/ 公司卡 / 现金 / 已由业主直付 |
| 9 | 是否业主计费 Owner-billable | 开关 | ✅ | 由房源+科目自动预填，可手动改 |
| 10 | 说明 Description | 文本域 | ✅ | 干什么用的 |
| 11 | 收据 Receipt | 文件（多张） | ✅ | 图片/PDF，支持拍照 |
| 12 | 报销给谁 Reimburse to | 文本 | 条件 | 仅当支付方式=个人垫付 |

**自动生成字段**（提交人看不到，后台写入）：提交时间戳、提交 ID、Drive 文件链接、状态、审批人、审批时间、QB 同步状态、提交 IP/UA（防重复）。

### 2.2 文件命名规范

```
2026-08-14_Puzzle-Point_Repairs_Home-Depot_87.43_Jing.jpg
    日期      房源简码     科目      商家      金额   提交人
```

多张收据自动加序号：`..._Jing_1.jpg`、`..._Jing_2.jpg`

规则：
- 日期用 `YYYY-MM-DD`，保证文件名排序 = 时间排序
- 所有分段内的空格 → `-`；去掉 `/ \ : * ? " < > |` 等非法字符；去掉重音符号
- 商家名截断到 20 字符
- 金额不带 `$`、不带千分位（`1234.56`）
- 文件名重复时自动追加 `-2`、`-3`

**为什么这样排**：日期在前保证时间排序；房源第二位，Drive 里按名字搜房源一搜一个准；金额在文件名里意味着不打开图片就能核对账。

### 2.3 归档路径

```
📁 Expenses
   ├─ 📁 Trust
   │    ├─ 📁 Puzzle-Point
   │    │    ├─ 📁 2026-08
   │    │    │    └─ 2026-08-14_Puzzle-Point_Repairs_Home-Depot_87.43_Jing.jpg
   │    │    └─ 📁 2026-07
   │    ├─ 📁 Ocean-Spray
   │    └─ 📁 …（每个房源一个）
   └─ 📁 Valta-Realty
        ├─ 📁 Office
        └─ 📁 2026-08
```

对应你 QuickBooks 的结构：**文件夹第一层 = QB Location，第二层 = QB Class**。月结时按文件夹逐个对账，路径本身就是维度。

⚠️ 待确认：Valta Realty 自己的开支是否也想按房源/部门分子文件夹，还是只按月份平铺。

## 3. 架构

```
   手机 / 电脑浏览器
   ┌──────────────────────────┐
   │  报销表单（单页 HTML）      │  ← 公开链接，无需登录
   │  · 房源搜索  · 文件名预览    │
   │  · 拍照上传  · 中英切换      │
   └────────────┬─────────────┘
                │ HTTPS POST (base64)
                ▼
   ┌──────────────────────────┐
   │  Google Apps Script       │  ← 以你的身份运行
   │  Web App (doPost)         │
   │  1. 校验 + 去重            │
   │  2. 生成文件名 + 建文件夹    │
   │  3. 存 Drive              │
   │  4. 追加 Sheet 一行         │
   │  5. 邮件/通知              │
   └────┬────────────────┬────┘
        ▼                ▼
   📁 Google Drive   📊 Expense Ledger Sheet
    （改名归档）        （结构化流水）
                          │
                          ├─→ 月度汇总（数据透视 / 报表页）
                          └─→ QuickBooks 导入文件
```

**为什么选 Apps Script Web App**

- 部署成 "Anyone with the link · Execute as me" → **提交人零账号**，文件却存进你的 Drive
- 零托管费用、零服务器运维，全部在你现有的 Google Workspace 内，数据不出门
- Drive / Sheet / Gmail 原生调用，不用管 OAuth
- 缺点：单次请求 6 分钟上限、文件上传约 50MB 上限 —— 对收据图片完全够用

**不选的方案**

- ❌ Google Form + 脚本：附件上传强制 Google 登录，清洁工直接卡死
- ⏸ 完整 Web App（Next.js + Vercel + Postgres）：能做 OCR 自动识别金额、审批推送、离线提交。**先不做**，等第一期跑顺了、量上来了再迁移（Sheet 数据可直接导入）

## 4. QuickBooks 对接

这是方案里唯一有技术风险的部分，分两条路：

### 路线 A：导出 QB 可导入文件（第一期，推荐）
Sheet 上加一个"生成 QB 导入文件"按钮，按已审批且未同步的行生成 CSV：每行带 Date / Vendor / Account / Location / Class / Amount / Memo / Billable。人工在 QBO 里 Import 一下。

⚠️ **需要验证**：QBO 的原生 CSV 导入对 Location/Class 的支持程度因订阅版本而异（Plus/Advanced 才有 Location）。可能需要走 Journal Entry 导入格式，或用 Transaction Pro 这类导入工具。**这一步我需要看一眼你 QBO 的版本和现有导入界面才能定死格式。**

### 路线 B：QB API 直连（第二期）
注册 Intuit 开发者应用，Apps Script 里用 OAuth2 库拿 token，审批通过后自动 `POST /purchase` 建一条支出并把 Drive 收据作为 Attachable 挂上去。做成之后是真正的"一次成型"，但需要处理 token 刷新、沙盒测试、错误重试。

**建议**：第一期做路线 A，把字段结构完全按 QB API 的形状设计，第二期升级时后端换个出口就行，表单和 Sheet 都不用动。

## 5. 上传后的邮件通知

提交成功的那一刻，Apps Script 自动发信（Gmail 原生调用，不用配 SMTP）。

### 5.1 发给谁

| 收件人 | 触发条件 | 来源 |
|---|---|---|
| **房源负责人** | 每一笔 | `Properties` 配置表里每个房源一列 `Owner Email` |
| **会计（Saira）** | 每一笔（CC） | 常量配置 |
| **你（Thao）** | 金额 > ⚠️`$500` | 常量配置，阈值可调 |
| **提交人本人** | 每一笔（回执） | 让清洁工/维修工确认"交上去了"，减少重复提交和微信追问 |

⚠️ 待确认：房源负责人是按房源指派（Jing 管东区、Shaya 管 Grayland 这种），还是按科目指派（维修类都发给某人）？我按前者做的，改成后者也只是配置表换一列。

### 5.2 邮件长什么样

主题行做成一眼能判断的格式，方便你在手机上扫：

```
[Expense] Puzzle-Point · Repairs · $87.43 · Jing
```

正文：
- 收据缩略图直接内嵌（不用点开附件就能看清楚）
- 全部字段一张表（房源 / 科目 / 商家 / 金额 / 说明 / 付款方式 / 是否业主计费）
- Drive 文件直达链接
- **两个按钮：Approve / Reject** —— 点一下就把 Sheet 里那行的状态改掉，不用打开 Sheet

> Approve/Reject 按钮的原理：Apps Script 的 `doGet` 带一个一次性 token，点击即执行。这是"审批"最轻量的实现方式，不需要额外系统。

### 5.3 频率控制

一天几十笔的话，逐笔发信会变成噪音。建议：

- **房源负责人**：逐笔实时发（他们要马上知道自己房子花了钱）
- **会计**：改成每天下班一封汇总（当天所有提交列成一张表），除非金额超阈值才实时
- **你**：只收超阈值的 + 每周一封汇总

⚠️ 这个频率策略你定一下，我按你的习惯配。

## 6. 月度汇总报表

Sheet 里加一个 `Report` 页，按月生成：

- **按房源**：每个房源当月总支出、业主计费 vs 公司承担、环比
- **按科目**：清洁/维修/用品各占多少，找异常
- **按提交人**：谁提交了多少笔、待报销金额（发工资时直接用）
- **待办**：待审批笔数、缺收据的、金额异常的（比如同一房源同一天同商家两笔——大概率重复提交）
- **QB 同步状态**：哪些还没入账

外加每月 1 号自动发一封汇总邮件给你和 Saira（会计）。

## 7. 分期计划

| 期 | 内容 | 工作量 |
|---|---|---|
| **第一期** | 表单页面 + Apps Script 后端 + Drive 改名归档 + Sheet 流水 + 房源/人员配置表 + **提交后邮件通知** | 1–2 天 |
| **第二期** | 邮件里的 Approve/Reject 按钮 + 月度汇总报表页 + 定时汇总邮件 + QB 导入文件生成 | 1 天 |
| **第三期** | QB API 直连、收据 OCR 自动填金额、微信/短信推送 | 按需 |

## 8. 审批环节（你说没偏好，我的默认建议）

**提交即归档，事后审核**——不要卡在审批上，否则清洁工提交完不知道有没有成功，你也会变成瓶颈。

具体：
- 提交 → 文件立刻归档、Sheet 写入，状态 = `Pending`，同时发通知邮件（第 5 节）
- 房源负责人在邮件里点 Approve / Reject，或在 Sheet 里改下拉
- 只有 `Approved` 的行才会进 QB 导入文件和报销汇总
- 金额 > ⚠️`$500`（阈值待定）的提交，额外抄送给你

改主意随时可以加"提交后待审批才归档"，但我不建议——卡住审批的结果是提交人不知道有没有成功，然后回来微信问你。

## 9. 需要你提供 / 确认的东西

1. **房源清单**（你说会给）：房源全名 + 简码 + Trust/Valta 归属 + QB Class 名 + **负责人邮箱**。⚠️ **简码很重要**，它是文件名里的第二段，最好 ≤ 16 字符
2. **人员清单**：谁能提交（姓名 + 邮箱，用于回执）
3. **QB 科目全名和科目号**（对照第 2.4 节的草案）
4. **QuickBooks Online 的订阅版本**（Essentials / Plus / Advanced）——决定 Location 能不能导入
5. **Drive 里 `Expenses` 根文件夹放哪**（新建，还是挂在现有某个共享盘下）
6. **大额抄送的阈值**，以及第 5.3 节的邮件频率策略
7. **负责人是按房源指派还是按科目指派**
